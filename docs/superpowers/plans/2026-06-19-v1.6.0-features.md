# Xray Test Manager 1.6.0 Feature Batch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the twelve 1.6.0 enhancements (spec `docs/superpowers/specs/2026-06-19-v1.6.0-features-design.md`): cross-project execution support, traceability XLSX export, create-exec-from-bugs, six UX items, plus Test Environments, Execution Type, and precondition/requirement swap.

**Architecture:** Local-first Go (Wails) backend + React/TS frontend. All mutations go through the `pending_change` journal and commit to Jira via `syncer.Engine`. New live REST calls stay behind the demo short-circuit (`jira.isDemoURL`) and are marked `TODO(xtm)`. Backend logic is unit-tested against the store + demo client; the frontend has no test runner (typecheck via `npm run build`, then manual demo-mode verification).

**Tech Stack:** Go 1.25, `modernc.org/sqlite`, Wails v2, React + TypeScript (Vite), `github.com/xuri/excelize/v2`.

**Conventions for every task:**
- Branch is `feature/v1.6.0-batch` (already checked out). Each task is its own commit.
- Backend: write the failing Go test first, run it red, implement, run it green, commit. Run `gofmt -w .` before each commit.
- After any change to an exported `App` method signature, run `wails build` (or `wails dev` once) to regenerate `frontend/wailsjs`, then update `frontend/src/api.ts` if it enumerates the binding, then `cd frontend && npm run build` to typecheck.
- No em dashes in code comments or Jira text (user preference). Do not stage `CLAUDE.md` or local tooling files.
- Locate the approximate line anchors (`:~NNN`) by symbol search; they are guides, not guarantees.

**Rollout order (each independently shippable):** D → E → L → F → G → H → I → K → J → C → B → A. J and K share schema migration v25; do K before J or vice versa but bump `schemaVersion` only as each lands (K bumps to 24 if it lands before A; coordinate the final numbers in Task 12, see note). To avoid version churn, this plan assigns: **A1 = v24**, **J + K = v25** (land J and K together under one v25 block). If A lands last as planned, that ordering holds.

```go
// BulkReplacePreconditions, for each test, removes toRemove and adds toAdd to
// the test's current precondition set in a single set-replacement per test
// (one precondition_set pending change each). It is the bulk form of "swap".
func (r *Repo) BulkReplacePreconditions(profileID string, testKeys, toRemove, toAdd []string) (BulkEditResult, error) {
	var res BulkEditResult
	remove := toSet(toRemove)
	for _, tk := range testKeys {
		cur, err := r.ListTestPreconditions(profileID, tk)
		if err != nil {
			res.Failed = append(res.Failed, BulkEditFailure{Key: tk, Error: err.Error()})
			continue
		}
		next := make([]string, 0, len(cur)+len(toAdd))
		seen := map[string]bool{}
		for _, k := range cur {
			if remove[k] || seen[k] {
				continue
			}
			seen[k] = true
			next = append(next, k)
		}
		for _, k := range toAdd {
			if seen[k] {
				continue
			}
			seen[k] = true
			next = append(next, k)
		}
		if err := r.SetTestPreconditions(profileID, tk, next); err != nil {
			res.Failed = append(res.Failed, BulkEditFailure{Key: tk, Error: err.Error()})
			continue
		}
		res.Succeeded = append(res.Succeeded, tk)
	}
	return res, nil
}
```
